INFORME DE FALLOS VIGENTES DE LA API MANTIS - CJ DISTRIBUCIONES
Fecha de última verificación: 2026-07-16
Entorno: MantisFiccCasalinsPruWeb

ALCANCE
-------
Este documento contiene únicamente fallos de Mantis que aún no cuentan con una
prueba end-to-end exitosa. No incluye errores de Auraly, credenciales, teléfonos
ni cadenas de conexión.


M-01. CREAR PEDIDO NO TIENE UNA PRUEBA EXITOSA Y VERIFICABLE
============================================================
Severidad: Crítica
Endpoint: pwsCrearPedidoCasalins

Fallo vigente:
- No se ha obtenido una respuesta exitosa con bPedNum no vacío usando el contrato
  actual de Mantis.
- Por lo tanto, tampoco se ha podido demostrar que el pedido se creó una sola vez
  con el cliente, bodega, artículos y cantidades enviados.
- Los errores no entregan un código estable que permita distinguir llaves
  inválidas, artículo sin inventario, bodega inválida o fallo interno.

Solución mínima solicitada a Mantis:
1. Entregar un cliente de pruebas con LlaveNit y LlaveCliente válidas.
2. Entregar una bodega y un CodigoArticulos disponibles para una prueba controlada.
3. Devolver siempre bPedNum no vacío cuando la creación sea exitosa.
4. Devolver ErrorKey estable y descriptivo cuando falle.
5. Documentar el mecanismo de idempotencia para que un reintento por timeout no
   cree un pedido duplicado.

Criterio de aceptación:
- Una solicitud válida crea exactamente un pedido y devuelve bPedNum.
- Reintentar la misma operación con la identidad idempotente acordada no crea un
  segundo pedido.


M-02. CONSULTAR PEDIDO NO DEVUELVE RESULTADO NI ERROR ÚTIL
==========================================================
Severidad: Crítica
Endpoint: pwsConsultarPedidoCasalins

Fallo reproducido:
- Consultar el NroPedido APED000036 incluido en la colección entregada por Mantis
  devolvió únicamente {"ErrorKey":null}.
- Consultar por cliente y rango de fechas produjo la misma respuesta sin cabecera,
  detalle, artículos, cantidades ni explicación.
- No es posible diferenciar pedido inexistente, filtro inválido o fallo interno.

Impacto:
- No se puede verificar el pedido retornado por CrearPedido.
- No se puede importar historial de compras para aprender preferencias del cliente.

Solución mínima solicitada a Mantis:
1. Documentar los formatos exactos de NroPedido, IdeClientes, FechaInicial y
   FechaFinal.
2. Entregar un NroPedido de pruebas vigente.
3. En éxito, devolver cliente, fecha, bodega y detalle con código y cantidad.
4. Si no existe, devolver un ErrorKey estable como PEDIDO_NO_ENCONTRADO.

Criterio de aceptación:
- Consultar el bPedNum retornado por CrearPedido devuelve exactamente el cliente,
  la bodega, los códigos y las cantidades enviados al crearlo.


PRUEBA END-TO-END PENDIENTE PARA CERRAR AMBOS FALLOS
====================================================
Mantis debe suministrar:
- LlaveNit y LlaveCliente válidas.
- Una bodega válida.
- Un artículo con inventario.

Con esos datos deben pasar, en orden:
1. Crear el pedido y recibir bPedNum.
2. Consultar ese bPedNum.
3. Verificar cliente, bodega, artículo y cantidad.
4. Reintentar de forma idempotente y comprobar que no se duplicó.
